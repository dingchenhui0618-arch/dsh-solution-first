## 先选路径，再动手（用户 <YYYY-MM-DD> 要求）

任何非平凡任务，动手前先用 30 秒回答三问，并把结论作为**回复的第一段**说出来：

1. **有没有现成的？** 按「本机已装能力 → 项目内既有实现 → 已有依赖 / 标准库 →
   社区项目 / skill / 库」的顺序找，都找不到才自己写。**禁止默认从零实现。**
2. **最省力的路径是什么？** 至少对比两条路（直接用 / 改造 / 局部借鉴 / 自建），
   一句话说明为什么选它、**放弃了什么**。
3. **怎么算做完了？** 先说清验收标准。标准不清楚就先问，**不要先动手写代码**。

展开流程见 `solution-first` skill。重要任务（新建项目 / 改架构 / 大重构）
用宿主的计划模式入口开头（DeepSeek Harness 里是 `/plan <需求>`），先交计划再审。

**例外**：只影响一两个文件、目标明确的改动直接做，但要用一句话说明为什么跳过上面三步。
**禁止**：产出没有验收标准、只为「看起来做了很多」的代码。

## 开源同步与推送前检查（用户 <YYYY-MM-DD> 要求）

开发成果持续开源同步到 GitHub。执行规则：

- **默认**：项目收尾时建公开仓库并推送。
- **推送前强制三步检查，缺一不可**：
  1. **密钥扫描** —— 扫 API key / token / `.env` / 私钥 / 连接串。命中即停。
  2. **`.gitignore` 核对** —— 确认 `.env`、凭据目录、依赖目录、构建产物、大文件已排除。
  3. **无关文件清理** —— 临时文件、调试脚本、截图、第三方源码副本不提交。
- **绝不推送**：客户资产、私有源码、凭据、以及宿主的个人配置文件目录
  （例如 `$DSH_HOME/`）。
- **停下来问用户**：任何一步命中、或不确定某个文件能不能公开时，先问，**不自动推**。
- 在 `<你的项目根目录>` 下建仓库；需要挂进 agent skill 目录时用 junction / symlink，
  不要留两份副本。
- GitHub 账号：`<你的 GitHub 账号>`（`gh` CLI 已登录时可直接 `gh repo create`）。
